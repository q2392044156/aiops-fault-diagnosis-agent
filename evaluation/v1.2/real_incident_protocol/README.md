# v1.2 真实故障数据协议

状态：`FROZEN_FOR_DATA_COLLECTION`

本协议用于收集经过授权、脱敏并能追溯标签来源的 HDFS 真实故障事件。RC2 通过后即可按本协议开始 v1.2；当前不要求已经拥有 100 个真实故障，也不把公开 HDFS block 异常标签当作真实根因。

## 数据单元

一个 `incident_id` 对应一次有明确时间边界的故障事件，并关联：

- 脱敏日志引用与不可逆内容哈希。
- 指标序列引用、采样周期和缺失区间。
- 工单或复盘记录引用。
- 根因标签、标签可信等级和复核记录。
- 五个时间戳：故障开始、首次可观测信号、Agent 检测、人工确认、恢复。
- 诊断时点可见的数据快照；恢复结论和事后复盘不得进入该快照。

字段以 [incident.schema.json](incident.schema.json) 为准。原始日志、密钥、用户标识、主机名和未授权工单内容不得写入本目录。

## 隔离与切分

按时间、集群和故障族共同隔离。来自同一次故障、同一维护窗口或同一模板化演练的派生记录只能属于一个数据切分。测试集标签在发布候选冻结后才对评测流程揭盲。

## 指标可用性

只有根因标签达到 `confirmed` 或 `high` 可信等级时，才计算根因 Top-1、Top-3 和 MRR。只有所需时间戳均存在、定义一致且可审计时，才计算 MTTD。条件不满足时统一返回 `N/A`，不得用 0 或推测值替代。

## 人工责任

创建者、复核者和裁决者应记录独立身份、时间和依据。流程隔离的 AI 角色只能生成草案，不能代替组织级独立签署。
