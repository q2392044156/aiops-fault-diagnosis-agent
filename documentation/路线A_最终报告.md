# 路线 A 最终报告（一页版）

> 一句话：在真实注入的 HDFS 故障上，WSL 单机 68 例 Top-1 98.5%，Docker 81 例 Top-1 91.4%；失败主要不是"排错"，而是证据与召回。

## 1. 范围

| 实验台 | 拓扑 | 故障族 | 注入形态 |
| --- | --- | --- | --- |
| WSL（Hadoop 3.3.6） | 1NN + 1DN | DN_VOLUME、DN_HEARTBEAT | 只读 remount、kill DN + 2s 心跳 |
| Docker Compose | 1NN + 3DN | DN_VOLUME、DN_HEARTBEAT、NN_SAFE_MODE | dd 填盘、kill、safemode |

每条实例都包含五时间戳、脱敏日志/指标、SHA-256、冻结 Schema 校验、导入与真实诊断链路。两套数据**不能相加**。

## 2. 结果

| 指标 | WSL 68 | Docker 81 |
| --- | --- | --- |
| Top-1 | **98.5%**（CI [0.9213, 0.9974]） | **91.4%**（CI [0.8322, 0.9575]） |
| Top-3 | 100% | 93.8% |
| Top-5 | 100% | 93.8% |
| MRR | 1.00 | 0.9218 |
| 冻结测试集 | n=14，100% | n=30，90.0%（CI [0.7438, 0.9654]） |
| 分族 | 卷 38/38、心跳 9/10、安全模式 20/20 | 卷 21/28、心跳 27/27、安全模式 26/26 |

## 3. Docker 失败归因（81 例）

| 故障族 | 总数 | 命中 | 证据缺失 | 召回缺失 | 排序错误 |
| --- | --- | --- | --- | --- | --- |
| DN_VOLUME | 28 | 21 | 5 | 0 | **2** |
| DN_HEARTBEAT | 27 | 27 | 0 | 0 | 0 |
| NN_SAFE_MODE | 26 | 26 | 0 | 0 | 0 |
| **合计** | 81 | 74 | 5 | 0 | 2 |

读法：

- **卷满只剩 2 例排序、5 例证据缺失**；心跳与安全模式已全对；
- **心跳主要是召回问题**：13 例日志有信号，但心跳卡没进候选；
- 安全模式证据干净，26/26——证明链路本身没问题。

## 4. 六项工程能力

| 项 | 关键结果 |
| --- | --- |
| P0-1 工具路由 | 规则 93.3% > 受控 90.0% > 自由 66.7%；受控参数 100% 结构化，成本 3.6× |
| P0-2 轨迹评测 | 30 例封存：18 clean + 12 abstained，7.0 步、5.27 次工具、90.83% 覆盖，0 重试 |
| P0-3 上下文工程 | 压缩省 36.5% token，Schema/引用/双类证据 100% |
| P1-4 可观测性 | 单次诊断 29 个 span，6.73s 中 6.59s 在生成 |
| P1-5 红队 | 50 例（40 攻击 + 10 正常），40/40 拦截、0/10 误杀 |
| P2-6 MCP | 5 个只读工具，initialize/list/call 冒烟通过 |

## 5. 覆盖与未覆盖

**已覆盖**：3 个根因码、4 种注入动作、2 种拓扑、日志/指标/时间戳三类证据、冻结测试集与置信区间。

**未覆盖**：网络分区/丢包、慢盘/IO error、真实 ENOSPC、NameNode 不可用、块副本、JournalNode、HA、客户端写失败、多故障叠加、生产工单。

## 6. 结论

1. "只读卷故障 + 心跳丢失"可以稳定注入、采集、诊断，WSL 67/68；
2. Docker 的 91.4% 剩余问题很小：**5 例证据缺失、2 例排序**；心跳与安全模式全对；
3. 安全模式 26/26 说明"证据干净时链路可靠"；
4. 两套数字分别回答"能不能测出来"和"规模化后会怎样"，不能合并成一个准确率。
