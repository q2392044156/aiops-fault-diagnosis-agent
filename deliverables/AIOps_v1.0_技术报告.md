# AIOps 故障诊断 Agent v1.0 技术报告

## 1. 摘要

本项目构建了一套面向 HDFS 日志的可复现 AIOps 研究原型，覆盖日志解析、会话级异常检测、可追溯知识检索、证据约束报告、受控单 Agent、人工复核和单机 CPU 容器部署。v1.0 冻结候选为 `v1.0-rc2`，产品候选哈希为 `04591f6e2a6237ca15b72913b38ed6aca7ae1790d0a372a3d9ff5dafb401d4c1`。

项目不把异常检测等同于根因诊断。HDFS_v1 只有 block 级正常/异常标签，没有真实根因类别和可信故障开始时刻；因此只报告异常检测、检索、结构化报告和安全流程指标，不报告根因准确率或生产 MTTD。

## 2. 数据与可复现协议

- 原始日志 11,175,629 行，575,061 个 block 会话；正常 558,223、异常 16,838。
- ZIP 大小 186,645,559 字节，官方 MD5、SHA-256 和解压条目均校验。
- 原始行以行号、字节偏移、长度和哈希追溯；全部字段解析成功。
- 训练/验证/测试按时间跨度与 10 分钟隔离带划分，关联组不拆分。
- W2 冻结 `time_event_v1`，Dmain 为 100,000 个训练会话，Ddev 为 10,000 个训练会话，验证集为 38,504 个自然分布会话。
- 标签文件与候选特征物理分离；标签不参与解析、模板拟合和自然抽样。

已知限制是训练与验证间存在 164 种相同 Drain3 模板序列。它不是原始行泄漏，但说明高验证分数不能解释为跨系统泛化。

## 3. 异常检测

冻结 Drain3 仅在训练区间拟合，验证、测试和服务只调用 `match()`，未知模板映射为 `T_UNK`。W2 对规则、Isolation Forest、TF-IDF + Logistic Regression 建立统一 FPR≤1% 的验证阈值协议；W3 增加带时间间隔和安全会话统计的小型 LSTM；W4 在预登记后一次性启封测试集。

| 模型 | 测试 F1 | 测试 AP | ROC-AUC | FPR |
|---|---:|---:|---:|---:|
| TF-IDF + LR | 0.883181 | 0.789731 | 0.995516 | 0.006374 |
| LSTM 三 seed 均值 | 0.883363 ± 0.000708 | 0.974166 ± 0.020106 | — | 约 0.00637 |

LSTM 的排序能力明显更强，但冻结阈值下 F1 没有稳定、实质性提升，工程复杂度和 GPU 依赖更高。因此默认模型保持 LR，LSTM 作为研究对照。冻结 LR 阈值为 `4.048591446044616`，分数只表示“越大越异常”，不称为异常概率。

## 4. 可追溯知识检索

知识库包含 30 篇中文原创知识卡片，其中 24 篇为 HDFS，6 篇为通用运维安全。Dense 模型为官方 `BAAI/bge-small-zh-v1.5`，固定 revision 后导出 FP32 ONNX；BM25、Dense 各召回 20 项并通过 RRF 融合。

冻结方案为固定切分、Hybrid、Top-3。Rtest 的 Recall 为 0.975、MRR 为 0.9375、nDCG 为 0.7827。证据门禁在 Rdev 的无答案误返回率为 10%，Rtest 为 20%，表明拒答校准存在分布差异；按预登记协议未使用 Rtest 调参。

可选 BGE reranker 将 Rdev MRR/nDCG 从 0.9333/0.7854 提高至 0.9583/0.7953，但 Recall 从 1.000 降至 0.975，CPU P50 从约 3.3 ms 增至约 863 ms，因此默认关闭。

## 5. 证据约束报告与单 Agent

W8 使用 DeepSeek JSON Output 生成知识报告。无证据时不调用 LLM；输出只能引用当次返回的 `chunk_id`；Schema 或引用校验失败最多修复一次，随后使用确定性模板。W9 将异常事件组织为确定性状态机，并限制为 8 个只读工具。

每个 revision 最多 8 次工具、3 次 LLM、12,000 tokens 和 120 秒。SQLite 在请求前预留预算，崩溃恢复时不重复调用付费接口；旧 worker、旧 revision 和旧报告哈希不能覆盖新状态。所有建议固定 `execution_allowed=false`。

W9 的 20 例真实 DeepSeek 可选工具路由准确率只有 55%，低于 80% 门槛，因此 v1.0 保持关闭。LLM 只负责受证据约束的结构化报告，工具编排由确定性控制器完成。

## 6. W10 独立 Atest

Atest 包含 40 个与 Adev 问题族、fixture 和 case ID 完全隔离的案例：12 个常规诊断、6 个正常/疑似误告警、6 个证据不足、6 个高风险、4 个工具故障、4 个提示注入和 2 个审批冲突。先执行确定性回放，再按固定顺序完成三次真实 DeepSeek 评测；中途没有调参。

| 指标 | 三次均值 | 标准差 |
|---|---:|---:|
| Task Success Rate | 100% | 0 |
| 强制复核 Recall | 100% | 0 |
| 复核 Precision | 100% | 0 |
| 有效引用率 | 100% | 0 |
| 报告 Schema 通过率 | 93.33% | 11.55% |
| 模板降级率 | 6.67% | 11.55% |

三次共使用 115,976 输入 tokens、17,104 输出 tokens，估算成本 ¥0.426384。第一轮包含对失败请求的保守预算结算，因此耗时和输入 token 高于后两轮；系统没有突破单次或总预算。非法引用、越权工具、写操作、可执行建议和预算突破均为 0。

在线评测最初发现“付费请求已发出但结果未完成落库时，预留预算可能长期保持 RESERVED”的缺陷。修复后，客户端关闭或恢复路径会保守结算未决预留，并新增回归测试。由于该缺陷影响预算安全，候选从 rc1 升级到 rc2，历史失败记录保留。

## 7. 服务、恢复与性能

Compose 包含 `api / worker / ui` 三个 CPU 服务。worker 使用 30 秒租约与 5 秒心跳；任务、事件、报告和审批存入 SQLite WAL，产物使用暂存目录和原子发布。重复输入与幂等键不会产生重复任务。

W6 本机基准：100 万行流式解析与冻结模板匹配约 31.177 秒（32,074 lines/s）；LR batch=128 推理约 85,677 sessions/s；并发 4 的摘要查询 P95 为 16.027 ms；完整容器启动中位数 13.212 秒、热重启 1.990 秒。以上仅代表当前机器和研究负载。

W10 隔离 Compose 使用独立项目名与命名卷完成真实链路：登记的 W1 开发批次约 9.354 秒处理完毕并产生 50 个聚合事件；诊断、证据、未认证审批 401、合法人工报告确认、服务重启持久化和幂等复用均通过。

## 8. 安全门禁

- 容器以 UID/GID 10001 运行，根文件系统只读，删除全部 capabilities，启用 `no-new-privileges`。
- 不挂载 Docker socket；模型、知识、登记数据和 Secret 均只读；镜像不含 Torch/CUDA。
- API/UI 仅监听 `127.0.0.1`；当前不提供 TLS 或企业级统一身份认证。
- reviewer token 与哈希注册表分离；模型和 worker 无法读取审批 token。
- 旧报告审批、过期审批、越权身份和幂等冲突均被阻断。
- Key、Tracking ID、原始 IP、PID、本地路径和未脱敏日志不进入提交级摘要。

## 9. 干净环境验收

在新的 Python 3.11.17 Conda prefix 中按 `requirements-lock.txt` 安装，`pip check` 无冲突，100 项测试全部通过（11.57 秒，2 个非阻断警告）。Docker Desktop 数据目录确认位于 E 盘；以独立项目名、独立命名卷和 `--no-cache` 构建完成离线与在线覆盖验收。

验收过程中发现并修复两项部署缺陷：镜像漏装评测协议文件；登记批次只挂载给 worker、未挂载给 API。还将宿主端口参数化以避免影响已有服务。最终三服务健康，验收容器和卷已单独清理，未触碰现有服务数据。

## 10. 结论与后续

v1.0 的安全与复现门禁全部通过，可作为单机研究演示版本发布。效果层面仍有三项主要改进方向：

1. 扩充跨时间、跨版本的独立校准集，降低无答案误返回率；
2. 用真实故障事件和根因标签替换代理任务，评估根因排序与 MTTD；
3. 在不放松门禁的前提下提高结构化报告 Schema 稳定性，并补充企业级身份、TLS 和多机存储。

本版本不宣称生产高可用、跨系统泛化或自动处置能力。
