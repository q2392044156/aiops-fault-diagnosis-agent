# v1.2 RC1 实施报告

## 状态

v1.2 RC1 已完成代码与本地工程验证，状态为 `IMPLEMENTATION_CANDIDATE`。它可以作为真实故障数据接入和后续独立评测的开发基线，尚不能表述为生产可用版本。

## 已实现内容

### 公开数据接入

- LogHub Hadoop：按 application 形成 55 个事件，输出脱敏日志模板。
- HDFS v3 TraceBench：按采集场景形成 364 个事件，输出组件、操作、边和失败计数等聚合摘要。
- 采用稳定分组切分：development 265、calibration 87、public independent_test 67。
- 诊断快照与评测标签物理分离；服务导入器只读取诊断快照。
- IP、路径、block ID、数字、密钥样式、URL、命令和提示注入文本经过过滤或占位替换。
- 相同事件与相同快照哈希幂等去重；同一 ID 的内容冲突直接拒绝。

### 诊断流程

- 新增只读工具 `read_trace_summary`，只返回聚合统计，不返回原始 Trace 或公开故障标签。
- Trace 组件进入确定性查询构建器，最多生成两个检索计划，使总工具调用继续受 8 次预算限制。
- 日志或 Trace 观测证据必须与知识文档证据同时存在，才进入 LangChain 报告链。
- 报告 Schema v2 支持 `trace` 证据和观测结束时间，所有建议仍固定 `execution_allowed=false`。

### Checkpoint 与恢复

- LangGraph 使用服务 SQLite 保存 checkpoint 和 pending writes。
- thread ID 固定为 `<release_id>:<diagnosis_id>:<revision>`。
- 图状态只含流程指针和哈希，不写入原始日志、标签或密钥。
- 业务数据库继续负责节点、预算、工具缓存、报告、审批和审计；checkpoint 不是第二套业务真相源。

### 真实故障入口

- 定义授权、保留期限、证据引用、五类时间戳、根因标签和诊断快照引用的严格 Schema。
- 导入前检查授权有效性、时区、截止时间与事后信息泄漏。
- 支持 validate、import、audit、delete 生命周期和删除审计。
- 标签或时间戳不合格时，根因指标与 MTTD 返回 `N/A`。

生命周期命令使用 `python -m aiops_diag.data incident`：`validate/import` 接受 `--input`，`audit/delete` 接受 `--incident-id`；导入、审计和删除还需指定 `--database`，删除必须提供 `--reason`。

## 数据与指标边界

- public independent_test 的标签已经公开，只能称为组隔离公开测试分区。
- TraceBench 故障注入标签没有经过真实工单、复盘和独立人员确认，不能称为生产根因。
- 当前没有合格的真实故障集合，因此生产根因 Top-1、Top-3、MRR、误报率和 MTTD 均为 `N/A`。
- 已揭盲的 v1.1 60 题和 30 题没有用于 v1.2 调参或正式验收。

## 后续进入真实评测的条件

1. 由有权限的人员按冻结协议导入经过授权和脱敏的事件。
2. 真实创建者、复核者和裁决者签署根因及时间戳记录。
3. 按时间、集群和故障族隔离新的封存测试集。
4. 冻结代码、配置、知识库、模型、数据和依赖哈希后只运行一次正式评测。
5. 依据正式结果决定是否进入单环境生产试点；当前 RC1 不自动执行任何变更操作。

## 启动与回退

v1.2 使用 `configs/service_v12_rc1.yaml` 和 `deployment/compose.v12-rc1.yaml`，隔离端口为 8012/8512。回退配置为 `deployment/compose.v12-rollback.yaml`，切回 Framework RC2 独立运行卷，不迁移或覆盖 v1.2 数据库。
