# v1.1 候选实施与验收状态

> 当前状态：`RESEARCH_CANDIDATE`。候选发布 ID 为 `agr11_b992eb6f0c657cce088c6f57`，目录为 `artifacts/releases/agent_v11_rc1_15`。默认服务仍使用冻结的 v1.0；本报告记录研究候选的工程与稳定性验收，不代表根因准确率或生产效果。

## 1. 已实现内容

### 1.1 检索协议与拒答门禁

- 建立 `evaluation/v1.1/` 协议，校验来源版本、发布日期、问题族、qrels、知识单元适用版本、跨 split 重复和 v1.0 题目泄漏。
- 建立 60 条 Apache HDFS 3.4.1/3.4.2 公开文档候选池，其中拟有答案 40 条、拟无答案 20 条，并提供不含拟定标签的盲化复核包。
- 提供外部复核、分歧裁决和新协议冻结工具。程序只能检查结构和哈希，不能证明复核者身份、独立性或标签语义。
- 候选拒答门禁只使用开发集和校准集确定阈值，当前小样本阈值约为 `0.55808`。两组各 2 条无答案样本的误返回为 0/2；该结果不能替代独立测试，也不能声称达到 ≤10% 的目标。

### 1.2 报告生成与安全门禁

- 缺少日志或知识证据时直接返回 `INSUFFICIENT_EVIDENCE`，跳过付费模型调用并强制人工复核。
- DeepSeek 只生成一条保守摘要。观测事实、候选原因、引用、缺失信息、限制和只读检查项由程序根据已验证证据构造。
- 引用必须属于本次允许的证据集合；操作性文本、提示注入、URL、命令和可执行建议均按失败关闭处理。
- 所有检查项的 `execution_allowed` 固定为 `false`；模型不能选择工具，也不能触发变更操作。
- 修复了终端节点恢复时重复记录 `request_human_approval` 的问题。候选报告使用稳定的重试身份，审批请求保留独立审计记录，但不参与报告生成来源哈希。
- 增加精确故障注入测试：在审批工具已记录、报告尚未发布时模拟 worker 中断，恢复后仍只有 1 条审批工具调用、1 份报告和 1 条审批。

### 1.3 候选发布与部署隔离

- Python 包版本为 `1.1.0rc1`，候选 Agent 为 `agent_v0.3_candidate`，候选 RAG 标识为 `rag_v0.2_candidate`。
- 候选清单绑定协议、校准结果、服务配置、提示词、候选源码、依赖锁、Dockerfile、Compose 文件和 `.dockerignore` 哈希。
- `configs/service.yaml` 继续加载 v1.0；`configs/service_v11_candidate.yaml` 和 `deployment/compose.v11-candidate.yaml` 仅用于显式候选环境。
- 容器镜像不包含 `.env`。DeepSeek 凭据和复核凭据通过 Docker Secret 文件挂载，验收记录不保存凭据值。

## 3. 历史覆盖观察

从公开 HDFS 已处理事件生成的 40 条脱敏报告输入中，旧 runbook 门禁返回文档 40/40，候选门禁返回 2/40。记录位于 `deliverables/results/v1_1_agent_runbook_coverage_rc1_09.json`。

这些事件没有文档相关性或真实根因标签，因此 40/40 和 2/40 只能表示返回覆盖差异。它们不能证明旧门禁更准确，也不能证明候选门禁效果更好。对应的 120 个事件—文档判断项仍等待独立人员复核。

## 4. 尚未完成的发布门禁

1. 未参与开发的 HDFS 领域人员需要复核 60 条公开候选，填写真实复核者信息，并由另一位人员裁决分歧；项目负责人还需完成身份、独立性和污染审计。
2. 复核通过后必须生成新的不可覆盖协议和候选发布，不得把 rc1_15 直接改名为正式版本。
3. 新冻结独立集只能运行一次正式验收，并报告 Top-3 Recall、MRR、nDCG、无答案误返回率、有答案误拒率及分版本结果。≤10% 是目标，当前没有独立测试实测值。
4. 真实故障事件、工单和根因标签尚未建立，因此根因准确率、误报率和 MTTD 继续标记为 N/A。
5. 统一身份认证、TLS、外部持久化、消息队列、备份恢复和容量测试属于后续受控生产试点范围，rc1_15 不具备生产发布条件。

## 5. 当前结论

rc1_15 已完成研究候选所需的报告稳定性、零执行安全门禁、预算控制、干净安装、容器启动、幂等和恢复验收。当前唯一阻止检索效果正式验收的前置条件是独立人工复核与冻结测试集；在该步骤完成前，默认后端保持 v1.0，不创建正式 `v1.1` Git tag，也不把在线稳定性结果表述为真实根因诊断效果。
